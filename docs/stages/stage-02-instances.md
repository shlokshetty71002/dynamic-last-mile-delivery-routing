# Stage 02 — Dynamic delivery instances

## Goal

Let the user choose the depot, number of stops, and actual locations by five input modes, mutate
the selection, and save/load it without embedding a fixed `N`.

## Scope

In scope: schema, mutable builder, presets, addresses, coordinates, seeded random nodes, map-click
API, validation, and JSON. Matrix cost updates are Stage 3; map-click widgets are Stage 10.

## Design

`DeliveryInstance` is immutable; `n_stops` derives from `len(stops)`. `InstanceBuilder` owns
changes and reports invalidated nodes. Ambiguous geocoding returns candidates. Portable canonical
instances store coordinates/null nodes and resolve in shared workflows
([ADR-0005](../adr/ADR-0005-portable-instances-and-thin-ui.md)).

## Interfaces

- `Stop`, `Depot`, `DeliveryInstance` — frozen schema-versioned models.
- `InstanceBuilder.set_depot_from_*`, `add_stop_from_*`, `add_random_stops` — all input modes.
- `move_stop`, `remove_stop`, `rename_stop`, `build` — mutation and validation.
- `DeliveryInstance.save/load` — lossless JSON.
- `dlm instance presets|create|random|show|map` — headless workflows.

## Data & assumptions

`1≤N≤50`; `1≤K≤N`; default service is 180 seconds; demand defaults to zero. Duplicate resolved
nodes are rejected. Snap guard defaults to 500 m. Catalogue contains 46 named Dublin references.

## How to run

```bash
dlm instance presets
dlm instance create --name demo --depot-preset "Dublin Port" \
  --stop-preset "Trinity College Dublin" --stop-preset "UCD Belfield" \
  --output data/instances/demo.json
dlm instance map data/instances/demo.json --output results/demo.html
```

## Acceptance criteria

- ✅ Tests cover dynamic N edge sizes and canonical N=8/20/40 files.
- ✅ Add/remove/move, duplicate-node rejection, and lossless save/load are tested.
- ✅ Coordinate-only files resolve to the active graph without source mutation.
- ✅ Ambiguous address candidates and readable snap failures are tested.
- ✅ UI passes map clicks into the same builder API.

## Results / evidence

`small-n8.json`, `medium-n20.json`, and `large-n40.json` are deterministically regenerated by
`scripts/generate_report_instances.py`; catalogue threshold and exact sizes are regression tests.

## Known limitations

Address resolution requires external Nominatim on first query. Coordinate equality does not prove
the selected point is the best loading entrance. Time windows are stored but not optimised.
