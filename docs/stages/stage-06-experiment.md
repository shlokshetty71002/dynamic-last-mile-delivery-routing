# Stage 06 — Execution, replanning, and T1/T2/T3

## Goal

Measure the normal route, frozen-order disrupted execution, realistic first-discovery replan, and
full-information oracle in one serialisable experiment.

## Scope

In scope: reactive/omniscient information enum, edge execution, detours, sunk state, remaining-stop
replan, no-regret fallback, partial service, metrics, run IDs, result/config files. Population
statistics arrive in Stage 7.

## Design

Reactive T2 follows baseline edge paths and detects the first missing edge. T3 starts at that actual
node with elapsed cost and unserved stops. Omniscient freezes order but reroutes each leg from t=0.
T3-oracle reorders from t=0. [ADR-0003](../adr/ADR-0003-objective-service-and-information.md)
and [ADR-0004](../adr/ADR-0004-no-regret-replanning.md) fix these semantics.

## Interfaces

- `InformationModel` — `reactive` or `omniscient`.
- `execute_frozen_routes(...) -> ExecutionRecord` — T2 and discovery state.
- `replan_at_first_discovery(...) -> ReplanRecord` — sunk prefix plus T3.
- `Experiment.run() -> ExperimentResult`, `Experiment.write(root) -> Path`.
- `compare_delivery(...)`, `dlm compare` — shared workflow and complete output bundle.

## Data & assumptions

Elapsed drive/service time is seconds; distance metres. Infeasible metrics are null and stop IDs
remain recorded. Headline saving uses reactive T3, never T3-oracle. Sustainability defaults are
recorded model factors.

## How to run

```bash
dlm compare --instance data/instances/small-n8.json \
  --scenario scenarios/oconnell_march.yaml \
  --information-model reactive --output-dir results/small-oconnell
```

## Acceptance criteria

- ✅ Non-touching disruption gives exact `T1=T2=T3` (primary regression test).
- ✅ A touched route makes a detour and finite T3 cannot exceed T2.
- ✅ Reactive T2 is not cheaper than omniscient T2 on the controlled fixture.
- ✅ Replan uses actual discovery node, remaining stops, sunk cost, and original depot.
- ✅ Unreachable cases produce structured partial/infeasible service.
- ✅ Repeated experiment/config bytes are identical.

## Results / evidence

Worked fixture example: if T2 is 120 s and the accepted T3 is 96 s, saving is
`100×(120−96)/120 = 20%`. Fixture tests assert actual calculated records rather than this
illustration; real Dublin values come from `result.json` generated by the command above.

## Known limitations

Discovery occurs at the blocked edge, replanning occurs once, and the driver has exact shortest
paths thereafter. The no-regret policy can conceal candidate-heuristic deterioration only by
explicitly flagging fallback, not by deleting the case.
